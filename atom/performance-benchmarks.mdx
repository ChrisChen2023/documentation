本页提供 ATOM-01 存算一体 SoC 在主流边缘 AI 模型上的实测性能基准数据，涵盖推理延迟、吞吐率、推理功耗与单次推理能耗四项关键指标。所有数据均在 ATOM-EVB 评估板上实测采集，为工程师评估方案选型、制定功耗预算及系统性能规划提供可靠的量化参考。基准测试结果同时与 Arm Cortex-A55 CPU 基线进行了横向对比，以直观呈现 ATOM 存算一体架构在边缘推理场景下的能效优势。

## 测试方法与条件

| 测试条件 | 说明 |
|---|---|
| **测试平台** | ATOM-EVB v1.1（ATOM-01 Rev B） |
| **量化精度** | INT8（另有标注的除外） |
| **批处理大小** | Batch Size = 1（单帧推理） |
| **测试迭代次数** | 1000 次，取平均值 |
| **预热** | 正式计时前执行 50 次推理预热，排除首帧 eReRAM 编程时间 |
| **功耗测量** | 通过板载 INA226 电流采样芯片测量 ATOM-01 整体供电功耗 |
| **运行时版本** | atomrt 1.2.0 |
| **环境温度** | 25°C ± 2°C |
| **CPU 基线平台** | Arm Cortex-A55 @ 1.8GHz，单核，AArch64，TFLite 2.12 INT8 运行时 |

<Note>
  延迟数据为端到端推理延迟，包含数据传输至 CIM 阵列、模拟计算、ADC 采样及数字后处理全流程时间，不含图像预处理（resize、normalize）时间。功耗为推理执行期间的平均功耗，不含模型加载阶段。
</Note>

### 主要模型基准

| 模型 | 任务类型 | 精度 | 延迟 (ms) | 吞吐率 (FPS) | 功耗 (mW) | 能耗/次 (μJ) |

### INT8 vs INT4 对比（MobileNetV2）

| 精度 | 延迟 (ms) | 吞吐率 (FPS) | 功耗 (mW) | 能耗/次 (μJ) | ImageNet Top-1 准确率 |
|---|---|---|---|---|---|
| INT8 | 0.8 | 1250 | 480 | 384 | 71.8% |
| INT4 | 0.4 | 2500 | 440 | 176 | 71.1% |
| 差值 | −0.4ms | +1250fps | −40mW | −208μJ | −0.7% |

<Tip>
  INT4 相比 INT8 能耗降低约 54%，准确率损失仅 0.7 个百分点。对于图像分类、关键词检测等对精度容忍度相对宽松的应用，**强烈建议优先使用 INT4** 以最大化能效。
</Tip>

## 与 CPU 基线对比

下表对比 ATOM-01 与 Arm Cortex-A55（1.8GHz，单核）在相同 INT8 量化模型上的推理性能差异：

| 模型 | 指标 | Arm Cortex-A55 | ATOM-01 | 提升倍数 |
|---|---|---|---|---|
| MobileNetV2 | 延迟 (ms) | 12.4 | 0.8 | **15.5×** |
| MobileNetV2 | 功耗 (mW) | 1200 | 480 | **2.5× 节能** |
| MobileNetV2 | 能耗/次 (μJ) | 14880 | 384 | **38.8× 节能** |
| ResNet-18 | 延迟 (ms) | 38.2 | 2.1 | **18.2×** |
| ResNet-18 | 能耗/次 (μJ) | 45840 | 1071 | **42.8× 节能** |
| YOLOv5s | 延迟 (ms) | 105.0 | 5.4 | **19.4×** |
| YOLOv5s | 能耗/次 (μJ) | 126000 | 2808 | **44.9× 节能** |
| DS-CNN | 延迟 (ms) | 2.8 | 0.3 | **9.3×** |
| DS-CNN | 能耗/次 (μJ) | 3360 | 126 | **26.7× 节能** |

<Info>
  延迟加速比介于 **8×–20×** 之间，能效提升介于 **25×–45×** 之间。能效优势远大于延迟优势，主要来源于 CIM 阵列消除了片外内存访问功耗。对于边缘设备而言，能效通常比绝对速度更重要，这正是 ATOM 存算一体架构的核心价值所在。
</Info>

<Note>
  ATOM-01 推理延迟抖动极低（标准差 < 50μs），主要原因是权重常驻片上 eReRAM，不存在传统 DDR 内存访问的带宽竞争与 DRAM 刷新导致的延迟不确定性。这使 ATOM 特别适合对延迟确定性（Deterministic Latency）有要求的工业控制与安全关键应用。
</Note>

## 功耗测量方法说明

ATOM-EVB 板载 **INA226** 双向电流/功率监测芯片，分别对 ATOM-01 核心供电（1.0V）、IO 供电（1.8V/3.3V）和模拟供电（2.5V）进行独立采样，采样周期 1ms，通过 I²C 接口由主机 MCU 读取。本文档中"功耗"数值为三路供电功率之和在推理稳态期间的时间平均值，不含模型加载（eReRAM 编程）期间的峰值功耗（模型加载峰值功耗约 800mW，持续约 200ms）。

通过 `atom-cli` 可实时查看功耗数据：

```bash
# 实时功耗监控（每秒刷新一次）
atom-cli status --watch --interval 1000

# 输出示例：
# ATOM-01 实时状态  [2024-06-01 12:00:01]
# ─────────────────────────────────────────
# 核心功耗  (VCORE 1.0V): 285 mW
# IO 功耗   (VIO   1.8V):  65 mW
# 模拟功耗  (VANA  2.5V): 155 mW
# 总功耗:                  505 mW
# 芯片结温:                 52°C
# 推理状态:               运行中 (resnet18-int8)
# ─────────────────────────────────────────
```

## 使用 INT4 进一步降低能耗

<Tip>
  对大多数图像分类、关键词检测和异常检测模型，**INT4 量化相比 INT8 能耗降低约 50%，准确率损失通常 < 1%**。在校准数据集充分、模型结构规则（无大量 Concat/Residual 跨分支连接）的情况下，INT4 是首选精度配置。以下是在各模型上使用 INT4 的建议：

  - **MobileNetV2 / EfficientNet-B0**：INT4 无明显精度损失，推荐使用
  - **YOLOv5s（目标检测）**：INT4 mAP 下降约 1.5%，对 IoU > 0.5 精度要求宽松的场景可接受
  - **DS-CNN（关键词检测）**：INT4 精度与 INT8 几乎等价，强烈推荐
  - **ResNet-18**：INT4 Top-1 准确率下降约 0.9%，大多数应用场景可接受
</Tip>
