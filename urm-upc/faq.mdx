<Accordion title="Q1：URM 与普通 SPI NOR Flash 有何不同，能否直接替换？">

**核心技术差异**

URM 基于昕原半导体自主研发的 **eReRAM（嵌入式阻变存储器）** 技术，与传统 SPI NOR Flash（浮栅或电荷陷阱型）在存储原理上存在本质区别：

| 特性 | URM（eReRAM） | SPI NOR Flash |
|---|---|---|
| 写入前是否需要擦除 | **不需要**，可直接覆盖写入 | 需要先块/扇区擦除 |
| 写入延迟 | 微秒级 | 毫秒级（擦除可达秒级） |
| 写入次数（耐久性） | ≥ 10⁶ 次（典型） | ≥ 10⁵ 次（典型） |
| 工作电压 | 1.8 V / 3.3 V | 1.8 V / 3.3 V |
| SPI 接口协议 | 兼容 SPI NOR 指令集超集 | 标准 SPI NOR 指令集 |

**直接替换可行性**

URM 的 SPI 引脚定义（/CS、CLK、SI、SO、/WP、/HOLD）和封装形式与主流 SPI NOR Flash（如 Winbond W25Q 系列）完全兼容，**可实现 Pin-to-Pin 硬件替换**。

在软件层面，URM 支持标准 SPI NOR 读指令（READ 0x03、FAST_READ 0x0B）以及 WREN/WRDI/RDSR 等常用命令，对于**只读或读多写少**的应用，现有固件无需修改即可直接使用。

若应用中存在**擦除操作（如 SE 0x20 / BE 0xD8 / CE 0x60 指令）**，由于 URM 无需擦除即可写入，这些命令仍然被接受（URM 内部将其等效为空操作或状态清除），不会导致错误，但建议在迁移后评估是否可从固件中移除擦除步骤以优化性能。

<Note>
如需详细的指令兼容性列表和替换验证清单，请向昕原半导体申请《URM 替换 SPI NOR Flash 迁移指南》。
</Note>
</Accordion>

<Accordion title="Q2：URM 写操作是否需要先擦除？最小写入单位是多少？">

**无需擦除，可直接覆盖写入**

这是 URM 相对于 SPI NOR Flash 最显著的优势之一。由于 eReRAM 采用阻变原理存储数据（通过改变存储单元的电阻值表示 0/1），写入新数据时无需预先将单元复位到某一状态，**可在任意地址、任意时刻直接写入新值**，原始数据会被自动覆盖。

**最小写入单位**

URM 的最小可寻址写入单位为 **1 字节（Byte）**，即可对任意单个字节独立写入，无页对齐要求。这与 NOR Flash 的页编程（Page Program，通常 256 字节对齐）模式有所不同：

| 写入模式 | URM | SPI NOR Flash |
|---|---|---|
| 单字节写入 | ✅ 支持，无对齐要求 | ⚠ 支持，但跨页需分次操作 |
| 任意长度连续写入 | ✅ 跨地址连续写入 | ⚠ 不可跨页，需分包 |
| 写入前擦除 | ❌ 不需要 | ✅ 必须 |

**写入完成确认**

每次写操作（字节写或连续写）发送后，需通过读取状态寄存器的 BUSY 位（SR1[0]）确认写入完成，BUSY 位清零后方可发送下一条命令。典型写入延迟为数微秒至数十微秒，远低于 NOR Flash 的页编程时间。
</Accordion>

<Accordion title="Q3：UPC MCU 的调试接口是什么？支持 OpenOCD 吗？">

**调试接口类型**

UPC MCU 内置标准 **ARM CoreSight SWD（Serial Wire Debug）** 调试接口，通过 2 线（SWDIO + SWDCLK）即可实现完整的断点调试、单步执行、寄存器/内存查看和性能跟踪功能。部分 UPC 型号同时提供 5 线 **JTAG** 接口，可在同一调试连接器上兼容两种模式。

**支持的调试器硬件**

| 调试器 | 接口 | 支持状态 |
|---|---|---|
| J-Link（SEGGER） | SWD / JTAG | ✅ 完整支持 |
| ST-Link V2/V3 | SWD | ✅ 支持 |
| DAPLink / CMSIS-DAP | SWD | ✅ 支持 |
| 昕原 UPC-LINK（评估板板载） | SWD | ✅ 原生支持 |

**OpenOCD 支持**

是的，UPC MCU 支持 OpenOCD。昕原半导体提供针对 UPC 系列的 OpenOCD 目标配置文件（`upc_xxx.cfg`），可用于命令行调试、GDB 联调和 CI/CD 自动化测试环境。

```bash
# 使用 J-Link 连接 UPC MCU 示例
openocd -f interface/jlink.cfg \
        -f target/upc_m0plus.cfg \
        -c "init; halt; reset halt"
```

<Tip>
昕原半导体评估板已板载 CMSIS-DAP 调试器，通过 USB 直接连接 PC 即可使用 OpenOCD 或 VS Code + Cortex-Debug 插件进行调试，无需额外购买调试器。
</Tip>
</Accordion>

<Accordion title="Q4：UPC 的 eReRAM Flash 如何烧录程序？支持哪些烧录工具？">

**片上 eReRAM 烧录原理**

UPC MCU 内置的 eReRAM 既作为程序存储器（Code Flash）使用，也可用作数据存储区（Data Flash）。烧录程序时，通过调试接口（SWD）将固件写入 eReRAM 的 Code Flash 区域，由片上 Bootloader 或调试接口直接驱动烧录时序。

**支持的烧录工具**

| 工具 | 方式 | 适用场景 |
|---|---|---|
| J-Flash（SEGGER） | SWD/JTAG | 开发调试、小批量烧录 |
| OpenOCD + GDB | SWD | 开发调试、脚本化烧录 |
| pyOCD | SWD/CMSIS-DAP | CI/CD 自动化烧录 |
| UPC Flash Programmer | SWD/UART ISP | 量产烧录（昕原自研工具） |
| UART ISP Bootloader | UART | 无调试器现场升级 |

**量产烧录推荐流程**

对于量产场景，昕原半导体推荐使用 **UPC Flash Programmer** 配合标准测试夹具，支持：
- 单机和多路并行烧录
- 烧录文件加密保护（防止固件被读出复制）
- 自动校验（烧录后回读比对 CRC）
- 日志记录与统计

**UART ISP 自升级**

UPC 内置 UART Bootloader，支持通过串口（UART ISP 模式）在系统内升级固件，适用于已部署设备的 OTA 更新场景，无需调试接口接入。

```bash
# 使用 pyOCD 烧录 HEX 文件示例
pyocd flash --target upc_m0p firmware.hex
```

<Warning>
烧录前请确认目标 UPC 型号与烧录工具中选择的设备配置一致，型号不匹配可能导致烧录失败或地址映射错误。
</Warning>
</Accordion>

<Accordion title="Q6：深度掉电模式唤醒后是否需要重新初始化？">

**唤醒后无需重新初始化**

URM 芯片从深度掉电模式（Deep Power-Down）唤醒后，其内部存储数据**完整保留**，所有已写入的数据不会丢失。芯片内部寄存器（包括状态寄存器）恢复到掉电前的状态，**不需要重新调用 `URM_Init()`**。

**唤醒时序要求**

退出深度掉电后，芯片需要一段恢复时间（**t_RES**，典型值约 30 µs，具体参见对应型号数据手册）才能接受新的命令。URM SPI 驱动的 `URM_ExitDeepPowerDown()` 函数内部已内置该延迟等待，应用层无需手动添加。

```c
/* 典型低功耗使用模式 */

/* 系统进入睡眠前 */
URM_EnterDeepPowerDown();
enter_system_sleep();           /* MCU 进入 Stop/Sleep 模式 */

/* 系统唤醒后 */
/* （无需 URM_Init，直接操作即可）*/
URM_ExitDeepPowerDown();        /* 内部已等待 t_RES */
URM_ReadByte(0x0000, &status);  /* 直接读取，无需重新初始化 */
```

**注意事项**

- 在深度掉电状态下，**任何 SPI 读写命令（包括 RDSR）均会被忽略**，返回值不可信。
- 若 MCU 复位（不是唤醒）后 URM 供电未中断，URM 可能仍处于深度掉电状态，此时 MCU 需要先调用 `URM_ExitDeepPowerDown()`，再调用 `URM_Init()`，以确保芯片处于已知就绪状态。

<Warning>
如果系统存在上电复位后不确定 URM 是否处于深度掉电的情况，建议在 `URM_Init()` 内部或应用初始化序列中无条件先发送一次 RDP 命令，这是安全且幂等的操作。
</Warning>
</Accordion>

<Accordion title="Q7：UPC MCU 是否支持 FreeRTOS 或其他 RTOS？">

**FreeRTOS 完整支持**

UPC MCU 基于 ARM Cortex-M0+ 内核，原生兼容 **FreeRTOS**（支持 V10.x 及以上版本）。昕原半导体提供经过验证的 UPC FreeRTOS 移植包，包含以下内容：

- `port.c` / `portmacro.h`：针对 UPC Cortex-M0+ 优化的上下文切换实现
- `FreeRTOSConfig.h` 参考配置（已针对 UPC 内存大小调优）
- 线程安全的外设驱动封装（UART、SPI、I²C）
- 低功耗 Tickless Idle 支持（与 UPC 深度睡眠模式集成）

**其他 RTOS 支持情况**

| RTOS | 支持状态 | 备注 |
|---|---|---|
| FreeRTOS | ✅ 官方移植包 | 推荐，有完整技术支持 |
| RT-Thread Nano | ✅ 社区移植 | 可联系昕原获取配置示例 |
| Zephyr RTOS | 🔄 规划中 | 预计下一版本 SDK 支持 |
| ThreadX（Azure RTOS） | ✅ 可用 | 标准 Cortex-M 移植即可 |
| 裸机（无 RTOS） | ✅ 完整支持 | HAL 库不依赖 RTOS |

**FreeRTOS 典型配置参考**

```c
/* FreeRTOSConfig.h（UPC MCU 典型配置节选） */
#define configCPU_CLOCK_HZ              48000000UL  /* UPC 主频 48 MHz */
#define configTICK_RATE_HZ              1000        /* 1 ms tick */
#define configTOTAL_HEAP_SIZE           (8 * 1024)  /* 8 KB 堆 */
#define configMINIMAL_STACK_SIZE        128         /* 最小任务栈（字） */
#define configUSE_TICKLESS_IDLE         1           /* 使能低功耗 Idle */
#define configUSE_MUTEXES               1           /* 使能互斥锁 */
#define configUSE_COUNTING_SEMAPHORES   1
#define INCLUDE_vTaskDelay              1
```

<Note>
使用 FreeRTOS 时，请参考《驱动开发指南》中的 RTOS 多任务保护章节，确保 SPI 总线访问受互斥锁保护，避免多任务并发访问引发总线冲突。
</Note>

<Accordion title="Q8：URM 在高温（85°C / 125°C）下数据保持时间是多少？">

**数据保持时间规格**

URM 系列存储芯片提供工业级和汽车级两个温度等级，对应不同的数据保持（Data Retention）指标：

| 温度等级 | 工作温度范围 | 数据保持时间（典型） | 适用标准 |
|---|---|---|---|
| 工业级（I） | –40°C ～ +85°C | **20 年**（85°C 条件下） | JEDEC JESD47 |
| 汽车级（A） | –40°C ～ +125°C | **10 年**（125°C 条件下） | AEC-Q100 Grade 1 |

**高温加速测试**

昕原半导体依据 JEDEC JESD22-A117 标准对 URM 进行高温数据保持（HTDR）测试，测试条件为在 150°C 高温下烘烤 1000 小时后读取数据，验证位错误率（BER）符合规格要求。

**影响数据保持的因素**

- **写入次数**：经历更多擦写循环的存储单元，数据保持时间相对缩短。在额定耐久次数（≥10⁶ 次）内使用，数据保持指标均满足上表规格。
- **存储温度**：非工作状态下长期存放建议在 25°C 左右，避免长期高温存储超出规格温度。
- **供电状态**：深度掉电或正常断电状态下数据保持特性无差异，eReRAM 数据在无电源条件下同样稳定保持。

**与 SPI NOR Flash 对比**

eReRAM 的数据保持机制与 NOR Flash（电荷泄漏模型）不同，高温下电荷泄漏率更低，在 **高温 + 高耐久** 场景下具有可靠性优势，特别适合工业控制、汽车电子和物联网等需要长寿命存储的应用场景。
